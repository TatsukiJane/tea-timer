# Модель данных и формат файла

Определения — в `src/types/brew.ts`. Zod-схемы там же: они охраняют **недоверенное**
направление (файл, приехавший из репозитория, или старая запись в IndexedDB).
Локальные записи создаются конструкторами `newMode` / `newPreset` / `newStep`.

## Сущности

```ts
BrewMode {
  id: string            // uuid
  title: string         // "Шу Пуэр 2018"
  image?: string        // путь от корня репо: "assets/6f1c2a3b.webp"
  notes?: string
  presets: VolumePreset[]   // минимум один
  createdAt, updatedAt: string  // ISO, всегда через toISOString()
}

VolumePreset {
  id: string
  vesselVolume: number  // мл
  leafGrams: number     // г, задаётся вручную под каждый объём
  steps: BrewStep[]
}

BrewStep {
  seconds: number       // обязательно
  tempC?: number
  pourMl?: number
  label?: string        // "быстрая промывка"
  rinse?: boolean
}
```

### Почему так

**Пролив — объект, а не число.** Кроме времени нужны температура и объём воды, и
они меняются от пролива к проливу. Объект расширяется без ломки формата.

**`tempC` и `pourMl` опциональны.** Не у всех чаёв ведётся температура. Обязателен
только `seconds` — простой таймер не должен требовать заполнять всё.

**Проливы лежат внутри пресета, а не режима.** На разном объёме посуды кривая
времени может отличаться. Если для конкретного чая они совпадают — в редакторе есть
«скопировать проливы» (`src/components/editor/CopyStepsDialog.tsx`), но модель не
мешает им расходиться.

**Граммовка задаётся вручную под каждый объём, а не считается от соотношения.**
Реальные чаи нелинейны, навязанный расчёт врал бы.

**`rinse` — флаг, а не разбор `label`.** Промывка не считается проливом при
нумерации: шаг после промывки — «Пролив 1», а не «Пролив 2»
(`infusionNumber` / `infusionCount` в `src/types/brew.ts`). Метка — свободный текст,
который пользователь может написать любыми словами, поэтому опираться на неё нельзя.

**`updatedAt` всегда нормализован через `toISOString()`.** От этого зависит
разрешение конфликтов: строки ISO-Z сравниваются лексикографически, и это корректное
сравнение по времени только если у всех значений одинаковая форма.

## Формат `.md`

Один режим = один файл `{modesDir}/{slug}-{id8}.md`. Frontmatter несёт полную
структуру и является источником истины при pull; таблицы под ним генерируются для
чтения глазами в Obsidian.

```markdown
---
id: 6f1c2a3b-1111-4222-8333-444455556666
title: Шу Пуэр «Лао Ча Тоу» 2018
image: assets/6f1c2a3b.webp
createdAt: 2026-07-01T08:00:00.000Z
updatedAt: 2026-07-26T10:00:00.000Z
notes: |-
  Куплен в Мосчае, октябрь 2025.

  Аромат: финики, сырая земля.
presets:
  - id: aaaaaaaa-1111-4222-8333-444455556666
    vesselVolume: 150
    leafGrams: 8
    steps:
      - { seconds: 10, tempC: 100, pourMl: 150, label: быстрая промывка, rinse: true }
      - { seconds: 25, tempC: 95, pourMl: 150 }
      - { seconds: 45, tempC: 95, pourMl: 150 }
---

# Шу Пуэр «Лао Ча Тоу» 2018

![Шу Пуэр «Лао Ча Тоу» 2018](../assets/6f1c2a3b.webp)

## 150 мл · 8 г

| Пролив   | Время | Темп. | Объём | Метка            |
|----------|-------|-------|-------|------------------|
| промывка | 0:10  | 100°  | 150мл | быстрая промывка |
| 1        | 0:25  | 95°   | 150мл | —                |
| 2        | 0:45  | 95°   | 150мл | —                |

## Заметки

Куплен в Мосчае, октябрь 2025.
```

### Правило №1: тело файла не парсится

Всё после frontmatter отбрасывается при чтении и перегенерируется при каждом push.
Это обеспечено тем, что парсер тела **просто не написан** — соблазн «ну хоть заметки
восстановить из `## Заметки`» — это то, как односторонний формат случайно становится
двунаправленным и два представления начинают расходиться.

**Если правишь файл руками в Obsidian — правь frontmatter.** Таблицы перепишутся.
Есть тест, который портит таблицу и проверяет, что это ни на что не влияет.

### Почему библиотека `yaml`, а не свой эмиттер

Решающий аргумент — корректность квотирования, а не косметика flow-стиля. Файл
должен переживать круговой рейс с произвольным пользовательским текстом: заголовок с
`:`, с `#`, с ведущим `-`, чисто числовой `2018` (не должен вернуться числом), метка
`да` (не должна вернуться boolean), многострочные заметки. Свой эмиттер обязан
переизобрести предикат безопасности plain-скаляра YAML, а ошибка в нём — ровно тот
класс баги, который тихо разрушает базу знаний. `js-yaml` отвергнут по другой
причине: у него нет управления стилем на уровне узла, поэтому им нельзя выводить
flow-стиль только для шагов.

Опции вывода (`src/md/serialize.ts`) со значением:

- `lineWidth: 0` — иначе длинный кириллический заголовок сложится на две строки:
  YAML остаётся валидным, но читать невозможно, а diff шумит.
- Опциональные ключи frontmatter подставляются spread'ом **в нужной позиции**, а не
  присваиваются после: порядок вставки ключей = порядок в файле, иначе `image` и
  `notes` уезжают под блок пресетов и голова файла перестаёт быть обозримой.

### Асимметрия пути к картинке — намеренная

Во frontmatter `image:` — путь от корня репозитория (`assets/x.webp`), в теле
markdown-ссылка относительная (`../assets/x.webp`), потому что файл лежит в
`modes/`. Obsidian нужен относительный путь, чтобы отрисовать картинку; слою
синхронизации нужен канонический. Не «исправляй» одно под другое.

### Имя файла

`{slug}-{id8}.md`. Слаг — транслитерация ru→lat (`src/lib/slug.ts`), обрезка до 40
символов по границе слова; для заголовка, который транслитерируется в пустоту
(только иероглифы или эмодзи) — фолбэк `mode`, чтобы никогда не получить
`-{id8}.md`. Авторитетный `id` всегда во frontmatter, поэтому имя файла —
презентация и может меняться: при переименовании чая слаг меняется, и синхронизация
пишет новый путь и удаляет старый.

### Что делает парсер с файлом, поправленным руками

`src/md/parse.ts`, через zod: генерирует отсутствующий `id` режима и пресета,
приводит числа из строк (`seconds: '25'` → `25`), нормализует дату к ISO, вырезает
неизвестные ключи, отклоняет файл без пресетов или с `seconds <= 0`. Ошибки
**возвращаются, а не бросаются**: один испорченный файл не должен обрывать весь pull.
