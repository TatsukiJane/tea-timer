# Настройка

## 1. Репозиторий-хранилище для чаёв

Отдельный от кода и **приватный**: в нём будут ваши записи.

1. Создайте новый репозиторий, например `tea-vault`, с видимостью **Private**.
   Пустой годится — папки `modes/` и `assets/` создадутся при первом сохранении.
2. Если хотите открывать его в Obsidian — просто клонируйте и откройте папку как
   vault. Отдельной настройки не нужно, `.md` с frontmatter Obsidian понимает сам.

Хранить чаи можно и в существующем vault: pull читает только настроенную папку
записей и посторонние файлы не трогает.

## 2. Токен

Нужен **fine-grained** personal access token с доступом только к этому одному
репозиторию.

1. GitHub → Settings → Developer settings → Personal access tokens →
   **Fine-grained tokens** → Generate new token.
2. **Resource owner** — ваш аккаунт.
3. **Repository access** → Only select repositories → выберите `tea-vault`.
4. **Permissions** → Repository permissions → **Contents: Read and write**.
   Больше ничего не нужно.
5. Срок жизни — на ваше усмотрение; по истечении приложение скажет «Токен
   недействителен или истёк», и надо будет ввести новый.
6. Скопируйте токен — GitHub покажет его один раз.

> Токен хранится в IndexedDB того браузера, где вы его ввели. Не вводите его на
> чужом устройстве. Если он утечёт, радиус поражения — один репозиторий с записями
> о чаях, а не аккаунт. Подробнее: `docs/sync.md`.

## 3. Настройки в приложении

Откройте «Настройки» (шестерёнка на главной):

| Поле | Значение |
|---|---|
| Владелец (owner) | ваш логин на GitHub |
| Репозиторий | `tea-vault` |
| Ветка | `main` |
| Папка для записей | `modes` |
| Папка для картинок | `assets` |
| Токен | вставьте PAT и нажмите «Сохранить» |

Нажмите **«Проверить доступ»**. Проверка только читает и ничего не пишет в
репозиторий. Ожидаемый ответ:

```
Доступ есть: ветка main, запись разрешена.
Репозиторий приватный.
Папка modes ещё не создана — появится при первом сохранении.
```

Если видите «Репозиторий не найден или токен не даёт к нему доступа» — почти всегда
репозиторий не выбран в списке доступных токену (fine-grained PAT отвечает на это
404, а не 403).

## 4. Хостинг на GitHub Pages

**Уже развёрнуто:** https://tatsukijane.github.io/tea-timer/ — Pages настроен на
GitHub Actions, ничего включать не нужно. Каждый пуш в `main` пересобирает и
публикует сайт через `.github/workflows/deploy.yml`; он же прогоняет линт, тесты и
проверяет, что service worker собран с правильным base path.

Если разворачиваете копию с нуля в другом репозитории:

1. Settings → Pages → **Source: GitHub Actions**. Это единственное ручное действие.
2. Запушьте в `main`.
3. Приложение будет на `https://<owner>.github.io/tea-timer/`.

Если репозиторий с кодом называется не `tea-timer`, поправьте `BASE` в
`vite.config.ts` — от него зависят и `base` сборки, и `navigateFallback` в service
worker.

## 5. Установка на устройство

**Android / Chrome, десктоп:** откройте сайт → в меню «Установить приложение».

**iOS / Safari:** «Поделиться» → «На экран «Домой»». Только так на iOS работают
Wake Lock и полноэкранный режим.

### Про iOS честно

Если заблокировать экран или уйти в другое приложение, iOS усыпляет
веб-приложение целиком: JavaScript не исполняется, звука и вибрации в конце пролива
не будет. Когда вы вернётесь, таймер покажет верное состояние («Готово»), но сигнал
уже не прозвучит. Поэтому:

- держите экран включённым (тумблер «Не гасить экран» включён по умолчанию);
- на экране заваривания на iOS показывается напоминание об этом.

Вибрации на iOS Safari нет вообще — соответствующий тумблер там будет неактивен.

## Локальная разработка

```bash
npm install
npm run dev        # http://localhost:5173/tea-timer/
npm run verify     # линт + тесты + сборка (то же, что в CI)
```

Проверить PWA можно только на собранной версии — в dev service worker отключён:

```bash
npm run build && npx vite preview --port 4173
npm run smoke      # прогон в headless Chromium по собранной версии
```
