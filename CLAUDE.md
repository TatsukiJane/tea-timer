# Работа над этим проектом

Чайный таймер — PWA для заваривания чая проливами. Локальный IndexedDB — источник
истины, GitHub — бэкап в виде `.md`-файлов для Obsidian.

Читай `docs/architecture.md` перед первой правкой. Ниже — то, что легко случайно
сломать, потому что «выглядит как улучшение».

## С чего начать

1. `docs/architecture.md` — слои, где что лежит, устройство таймера.
2. Раздел «Правила, которые нельзя нарушать» ниже — прочитать целиком, там
   неочевидные инварианты.
3. `docs/data-model.md` — если трогаешь модель или формат файла.
   `docs/sync.md` — если трогаешь синхронизацию.

**Прод уже развёрнут:** https://tatsukijane.github.io/tea-timer/. Пуш в `main`
публикует сайт через `.github/workflows/deploy.yml` — учитывай это, `main` не
черновик. Pages уже настроен на GitHub Actions, включать ничего не надо.

## Команды

```bash
npm run dev        # разработка
npm test           # vitest, окружение node, без jsdom
npm run lint       # oxlint
npm run build      # tsc -b && vite build
npm run verify     # lint + test + build — то же, что гоняет CI
npm run smoke      # e2e в браузере; нужен только предварительный npm run build,
                   # preview-сервер скрипт поднимает сам
npm run smoke:update  # отдельный e2e: автообновление применяется само, но не посреди
                      # пролива и не при открытом редакторе; тоже после npm run build
```

`npm run smoke` намеренно не входит в `verify` и в CI: ему нужен Chromium, а
`verify` должен работать где угодно. Он проходит весь путь по собранной версии —
создание чая, копирование проливов, нумерация с промывкой, шаг до конца, отсутствие
авто-перехода, повторяющийся сигнал и его отключение, уход вкладки в фон,
офлайн-загрузка из прекеша, очередь офлайн-записи, удаление. Плюс проверяет, что в Cache Storage нет ничего от `api.github.com`.

## Правила, которые нельзя нарушать

**Не парси тело markdown-файла.** Frontmatter — источник истины, таблицы под ним
генерируются из него и никогда не читаются обратно (`src/md/parse.ts`,
`src/md/tables.ts`). Соблазн «восстановить хотя бы заметки из `## Заметки`» — это
то, как формат становится двунаправленным и два представления начинают расходиться.
Если правишь файл руками в Obsidian — правь frontmatter.

**Заголовки таблиц в MD — не строки интерфейса.** Они живут константами в
`src/md/tables.ts`, а не в `src/i18n/ru.ts`. Иначе смена языка UI перепишет все
файлы в репозитории.

**Таймер не накапливает elapsed.** `src/timer/engine.ts` хранит либо абсолютный
дедлайн (`running`), либо остаток (`paused`), и конвертирует одно в другое.
Не добавляй поле «прошло столько-то» — оно ломает поведение при троттлинге
фоновой вкладки. Все переходы принимают `now` аргументом и не читают часы сами:
на этом держатся тесты со скачками времени.

**Не добавляй runtime-кеш в service worker.** В `vite.config.ts` стоит
`runtimeCaching: []`, и это несущее решение. Единственный сетевой трафик —
`api.github.com`; его кеширование (а) подсунет устаревшие `updatedAt`/`sha` в
разрешение конфликтов и испортит данные, (б) может записать запрос с PAT в Cache
Storage. Есть проверка в `e2e/smoke.mjs`, что в кеше нет ничего от GitHub.

**Время пролива вводится маской м:сс слева направо, а хранится в секундах.** Поле в
редакторе — маска из `src/lib/duration.ts`: сначала минуты, двоеточие ставится само
(`0 4 5` → 0:45, `2 0 0` → 2:00). Направление проверено на живом пользователе: набор
справа налево (когда цифры сдвигают предыдущие) отвергнут, не возвращай его. В модели,
в IndexedDB и в `.md` по-прежнему `seconds: 120` — не меняй единицы в модели, чтобы
«упростить» ввод. И не переводи поле обратно на `fill()` в e2e: маскированный
контролируемый input так теряет нажатия (см. комментарий у `setTime` в `e2e/smoke.mjs`).

**Повторяющийся сигнал планируется вперёд, а не играется по интервалу.**
`startAlarm()` в `src/timer/alarm.ts` раскладывает писки на аудио-часах сразу на 90 с
вперёд, а `setInterval` только продлевает горизонт. Заменить это на «играть очередной
писк каждые 2,4 с по интервалу» — значит получить сигнал, который в скрытой вкладке
звучит раз в минуту, то есть ровно в том случае, для которого он и нужен. И не забывай
`stopAlarm()` при размонтировании `BrewPage`: иначе остаётся пищащая страница, которую
нечем выключить.

**`registerType` — `'prompt'`, не `'autoUpdate'`, хотя обновление автоматическое.**
Новая сборка применяется сама (`src/components/pwa/AutoUpdate.tsx`), но перезагрузку
инициируем мы, а не плагин: `'autoUpdate'` перезагрузит страницу в момент готовности
worker'а — то есть посреди пролива или поверх недописанного чая. Момент выбирается по
`src/state/useBusy.ts` (идёт пролив / звучит сигнал / открыт редактор). Перезагрузку
делает сам `AutoUpdate` по `controllerchange`: встроенная в плагин срабатывает не
всегда (зависит от `isUpdate`). Проверяется `npm run smoke:update`.

**Температура живёт на пресете, а не на проливе.** Не возвращай `tempC` в
`BrewStep`: воду выставляют один раз, дальше она остывает сама, и поле на каждом шаге
и утомляет при вводе, и врёт про то, что она меняется. Парсер и миграция БД v1→v2
поднимают её из старых записей, предпочитая первый настоящий пролив, а не промывку.

**Токен не читается обратно в состояние компонента.** Он лежит отдельной строкой
`settings['token']` в IndexedDB. Не логируй его, не клади в URL, не вкладывай в
объекты ошибок, которые уходят в тост.

**Не удаляй локальные записи, если файл пропал в репозитории.**
`src/sync/syncService.ts` только считает их (`localOnly`). Автоудаление по одному
листингу — способ потерять всё.

**Push никогда не роняет сохранение.** IndexedDB уже закоммитил; при неудаче режим
остаётся `dirty`, и кнопка синхронизации подберёт его позже.

**Конфликты спрашивают, а не перезаписывают молча.** См.
`setConflictResolver` и `src/components/sync/ConflictHost.tsx`.

## Особенности тулчейна

- **TypeScript пин `~6.0.2`, не 7.x.** TS 7 не отдаёт публичный compiler API до
  7.1; `typescript-eslint` на нём не работает. Линтер — `oxlint`, ему compiler API
  не нужен.
- **`erasableSyntaxOnly` включён**: parameter properties в конструкторах запрещены,
  объявляй поля явно. Enum'ов тоже нельзя.
- **`verbatimModuleSyntax` включён**: для типов пиши `import type`.
- **Tailwind v4, конфига нет.** Вся тема — два блока `:root` / `.dark` между
  маркерами `THEME START` / `THEME END` в `src/index.css`. Компоненты ссылаются
  только на семантические токены (`bg-background`), никогда на конкретный цвет.
  Сменить тему = заменить эти два блока.
- **`src/components/ui/**` сгенерировано shadcn CLI.** Правки там помечены
  комментарием (в `sonner.tsx` заменён импорт `next-themes` на свой стор темы).
  При `shadcn add` новых компонентов проверяй, не тянут ли они `next-themes`.
- **Иконки** генерируются скриптом, а не хранятся как исходник дизайна: см.
  `docs/architecture.md`, раздел про иконки.

## i18n

Строки — в `src/i18n/ru.ts`, доступ через `t('ключ')`. Добавить английский =
завести `en.ts` того же типа `Dict` и зарегистрировать в `src/i18n/index.ts`;
компоненты трогать не нужно. Русские множественные числа — через `plural()` /
`countOf()`, а не зашитыми в строку.

Тексты интерфейса прошли редактуру по правилам UX-копирайтинга; сами правила
выписаны в шапке `src/i18n/ru.ts` — прочитай их, прежде чем добавлять строку.
Коротко: «вы» со строчной, кнопка — реплика пользователя («Сбросить», не «Сброс»),
лейбл называет данные, тумблер читается одинаково в обоих положениях, ошибка
говорит что случилось и что делать, «Внимание:» не пишем, точек в конце кнопок и
тостов нет. Слова «пресет» в интерфейсе нет — там «объём посуды», хотя в коде
сущность так и называется `VolumePreset`.

Часть строк дословно используется e2e-прогонами (`Промывка`, `Заваривать`,
`Добавить пролив`, `Настройки сохранены`, `Приложение обновлено` и ещё несколько) —
меняешь их, значит правишь и `e2e/*.mjs`.

## Тесты

Компонентных тестов нет намеренно — для личного приложения они стоят дороже, чем
ловят. Покрыто ровно то, где бага молчаливая и уничтожает данные: round-trip
markdown (плюс golden-снапшот файла), движок таймера, транслитерация и base64,
клиент GitHub и оркестрация синхронизации. Если меняешь эмиттер YAML —
golden-снапшот упадёт, и это правильно: он ловит «поменяли опцию и теперь
перезаписываются все файлы в репозитории».
